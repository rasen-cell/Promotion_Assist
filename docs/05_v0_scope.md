# 05. 縮小スコープ v0：「告知パック生成器」

リスク評価（`04_risk_assessment.md`）を受け、v0 は **外部 API に依存しない、ブラウザだけで完結する静的 Web アプリ** に絞る。サーバーもアカウントも持たない。

## 1. v0 の価値提案

> 作品と今回の更新内容を入れると、X / Bluesky / Threads / Misskey / Mastodon それぞれの作法に合わせた告知文と、縦書きの宣伝画像が 30 秒で揃う。各 SNS の公式「共有」画面を 1 タップで開いて投稿する。

- 作家の手作業（10〜15 分）のうち、**考える・整える・作る** をゼロにする。**送る** は本人の 1 タップに残す。
- 利用者の SNS 資格情報を預からない。作品サイトへ自動アクセスしない。運用費ゼロ。

## 2. スコープ

### 2.1 入る（v0）
| 機能 | 内容 |
|---|---|
| 作品の登録・保存 | 題名、URL、作者名、サイト種別、SNS 別タグセット。端末内（localStorage）に保存。JSON でエクスポート／インポート |
| なろう自動入力（任意） | ncode または作品 URL から題名・あらすじ・作者名・話数を取得。失敗時は手入力。利用者の操作でのみ呼ぶ |
| 更新の入力 | 告知種別（更新／新作／完結）、話数（範囲可）、話タイトル、話 URL、ひとこと、冒頭抜粋 |
| SNS 別文面生成 | 文字数計測（X 加重 280、Bluesky 書記素 300、Threads 500、Misskey 3,000、Mastodon 500）、リンク配置（X はリプ用テキストを別生成）、タグ上限、超過時の段階的短縮 |
| 言い回しローテーション | 冒頭句・結び句を作品ごとに「最近使っていないもの」から選ぶ |
| 宣伝画像 | 縦書き冒頭カード／話数バナー。1200×630 と 1080×1350。3 配色。PNG 保存とクリップボードコピー |
| 1 タップ投稿 | 各 SNS の公式共有インテント URL を開く（X: `x.com/intent/post`、Bluesky: `bsky.app/intent/compose`、Threads: `threads.net/intent/post`、Misskey/Mastodon: `{host}/share`） |
| ガード | 作品×SNS ごとに「前回の告知から N 時間」（X 12h、他 24h）以内なら警告。直近 7 日の同一文面を警告 |
| 履歴 | 「投稿した」を記録し、一覧表示 |

### 2.2 入らない（v0 では見送り）
- 自動投稿（API）、トークン保管、予約投稿
- 更新の自動検知、効果測定
- カクヨム等からの情報取得（手入力）
- 漫画ページの分割・イベント告知パック（v0 の検証後に追加候補）
- AI 文章補助

### 2.3 v0 → 次段階の判断
`04_risk_assessment.md` 4 章の条件を満たしたものから順に追加する。

## 3. プロトタイプ

`prototype/` に実装。ビルド不要の静的ファイル（HTML / CSS / ES Modules）。

```
prototype/
  index.html           画面
  styles.css
  app.js               画面の配線（保存・生成・コピー・インテント）
  src/limits.js        SNS 別の上限・計測方式・インテント URL の定義（設定の単一箇所）
  src/compose.js       告知文の組み立てと段階的短縮
  src/rotation.js      言い回しローテーション
  src/guard.js         告知間隔ガード・重複文面チェック
  src/intents.js       共有インテント URL の生成
  src/card.js          Canvas による縦書きカード／バナーの描画
  src/narou.js         なろう API アダプタ（任意・隔離）
  src/storage.js       localStorage の読み書き・エクスポート
tests/
  unit.test.mjs        node:test による単体テスト
  e2e.cjs              Playwright によるブラウザ通しテスト
```

### 3.1 動かし方
```
npm test          # 単体テスト
npm run e2e       # ブラウザ通しテスト（Chromium が必要）
npm run dev       # http://localhost:8080 で起動
```

### 3.2 設計上の要点
- **設定の単一箇所**：SNS 別の上限・計測方式・インテント URL は `src/limits.js` に集約。仕様変更時はここだけ直す。
- **純粋関数**：`compose / rotation / guard / intents` は DOM に依存せず、Node の単体テストで固定する。
- **フォールバック**：`Intl.Segmenter` 非対応、Clipboard 画像非対応、なろう API 失敗のいずれも機能停止にならない。
- **データはすべて端末内**：サーバー無し。エクスポート JSON で引っ越し可能。

## 4. 検証計画（v0 公開後 4 週間）
| 問い | 計測 |
|---|---|
| 「揃う」価値は実感されるか | 初回利用で 3 SNS 以上のインテントを開いた率 |
| 手作業の残りは許容されるか | 「画像を貼るのが面倒」「1 タップも面倒」の声の頻度 |
| なろう自動入力は使われるか | ncode 入力の利用率と失敗率 |
| 継続するか | 2 週目以降に再訪して生成した作家の割合 |
