# 04. リスク評価：外部依存と仕様変更リスク

`03_spec.md` の設計は、作品サイト 1 種（なろう API）と SNS 5 種（Bluesky / Threads / Misskey / Mastodon / X）の API に依存している。本書は各依存のリスクを評価し、依存を最小化したスコープ（`05_v0_scope.md`）を導く。

評価軸（各 1〜5）
- **P**：仕様変更・停止・規約変更が 12 か月以内に起きる確率
- **I**：起きた場合のコア価値（「告知が整う」）への影響
- **D**：変化の検知しやすさ（5＝自動で即検知、1＝ユーザー報告待ち）
- **R**：復旧・代替の容易さ（5＝即代替可、1＝作り直し）
- **スコア** = P × I × (6 − R) / D。大きいほど危険。

## 1. リスク台帳

| # | 依存 | 用途 | P | I | D | R | スコア | 主な懸念 |
|---|---|---|---|---|---|---|---|---|
| R1 | X API（BYOK） | 自動投稿 | 5 | 2 | 3 | 5 | 3.3 | 2023〜2026 で料金・階層が 4 回以上改定。従量課金の単価改定は予告なし。凍結判定の厳格化 |
| R2 | X 自動化ルール | 全般 | 4 | 4 | 2 | 3 | 24.0 | 「同一リンク連投」「外部ツール」への判定が年々厳しくなる。利用者アカウントの凍結は取り返しがつかない |

| R14 | Stripe・メール送信 | 課金・通知 | 1 | 2 | 4 | 4 | 1.0 | 汎用。代替容易 |

### 1.1 読み取り

1. **危険なのは「投稿 API」と「トークン保管」**（R2, R3, R7）。しかも投稿 API は「告知が整う」という中核価値そのものではなく、最後の 1 タップを省くだけの機能。
2. **なろう API（R8）は中程度**。公式・無料・安定だが、制限復活が公式に予告されている。「必須」ではなく「あれば便利」の位置に置けば影響は小さい。
3. **カクヨム等の非 API サイト（R10）は、取りに行かない限りリスクゼロ**。作者が入力・貼り付けする設計にすれば依存が消える。
4. **共有インテント URL（R12）とブラウザ標準機能（R13）は極めて低リスク**。ここに価値を載せると、外部仕様変更でサービスが止まる可能性が事実上なくなる。

## 2. 依存を減らした場合の価値の残り方

| 機能 | 03 の設計 | 依存を外した設計 | 価値の残存 |
|---|---|---|---|
| SNS 別の文面生成（文字数・リンク配置・タグ・言い回しローテーション） | サーバー | **ブラウザ内のみ** | 100% |
| 宣伝画像（縦書き冒頭カード等） | ブラウザ内 | **ブラウザ内のみ** | 100% |
| 1 日 1 回ガード・重複文面チェック | サーバー | **ブラウザ内（localStorage）** | 90%（端末をまたぐと共有されない） |
| 投稿 | API 自動投稿 | **公式共有インテントで本人が 1 タップ** | 80%（1 タップと画像添付の手作業が残る） |
| 作品情報の自動入力 | なろう API | **任意機能として残す。失敗時は手入力** | 70% |
| 更新自動検知 | なろう API ポーリング | **v0 では外す**（「更新したら開く」運用） | 0%（検証後に再検討） |
| 効果測定 | なろう API 日次 | **v0 では外す** | 0%（検証後に再検討） |
| 予約投稿 | サーバー | **v0 では外す**（インテントは即時のみ。Threads は公式予約機能で代替） | 0% |

結論：依存をほぼゼロにしても、作家が最初に体感する価値（「3 つの SNS 分の文面と画像が 30 秒で揃う」）は損なわれない。失うのは「無人化」の部分であり、それはユーザー検証が済んでから、最も安定したプラットフォームから順に足せばよい。

## 3. 残す依存への具体的な対策

| 依存 | 対策 |
|---|---|
| なろう小説 API（任意機能） | アダプタとして隔離。JSONP／fetch の失敗・タイムアウト（8 秒）は即座に手入力へフォールバック。呼び出しは利用者操作起点のみ（自動巡回なし）。応答項目は「無ければ空」で処理し、略号変更で落ちない |
| 共有インテント URL | プラットフォームごとに 1 関数に閉じ込め、URL テンプレートを設定ファイル化。文字数上限も同じ設定に置き、変更時は 1 か所の修正で済む |
| 文字数計測 | 各 SNS の計測方式（X 加重、Bluesky 書記素、Threads/Misskey コードポイント）を関数化し、単体テストで固定 |
| ブラウザ機能 | Clipboard 画像書き込みが不可なら PNG ダウンロードに自動フォールバック。`Intl.Segmenter` 非対応ならコードポイント計測に退避 |
| データ | 端末内（localStorage）のみ。JSON でエクスポート／インポートでき、サービス側にサーバーが無いのでデータ漏洩の面が存在しない |

## 4. 将来 API 連携を再検討する際の判断基準

| 追加候補 | 追加してよい条件 |
|---|---|
| Bluesky 自動投稿 | 利用者 50 名以上が週 2 回以上インテントで投稿しており、「1 タップも面倒」という声が上位 3 位以内。OAuth の仕様が 6 か月以上安定している |
| なろう更新検知 | 手動運用で「更新したのに告知を忘れた」が主要な離脱理由と分かった場合。API 制限の復活状況を確認したうえで、Pro 限定・作品数上限付きで導入 |
| Threads 自動投稿 | App Review が通ること。Threads 公式の予約投稿で代替できない需要がある場合のみ |
| X 自動投稿 | 導入しない（BYOK でも凍結リスクを利用者に負わせる）。インテントを維持 |
| カクヨムからの情報取得 | 公式 API が提供された場合のみ |
