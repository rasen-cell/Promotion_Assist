# 02. ニッチ選定とツール案

## 1. 前提：個人開発で成立する条件

| 条件 | 理由 |
|---|---|
| 無料 API だけでコア価値が成立する | X API は従量課金。無料枠に頼る設計は 2026 年時点で崩壊済み |
| スクレイピングに依存しない | なろう・カクヨムとも規約で禁止。凍結・BAN は作家の生命線を奪うため、利用者を巻き込めない |
| 汎用ツールと機能で競わない | 予約投稿・同時投稿は MultiPost（無料）や Buffer が既にある |
| 1 人で運用できるインフラ費（月数百〜数千円） | サーバーレス＋クライアント側処理で成立させる |
| 課金してもらえる「作家ならではの困りごと」を解く | 「宣伝疲れ」「毎回同じ作業」「効果が見えない」 |

## 2. ニッチ候補の評価

| # | 候補 | 需要 | 競合 | 実現性（個人） | 規約リスク | 評価 |
|---|---|---|---|---|---|---|
| A | 汎用 SNS 予約投稿（作家向け UI） | 高 | **強**（無料含む） | 高 | 低 | × 差別化不能 |
| B | **作品更新 → SNS 別最適化告知の自動生成・自動投稿（Web 小説・Web 漫画特化）** | 高 | 無し | 高（なろう API＋無料 SNS API） | 低（API/本人操作のみ） | **◎ コア** |
| C | 漫画ページ → SNS フォーマット変換＋投稿（4 分割・1p 目訴求・縦読み） | 中〜高 | 分割ツールのみ | 高（ブラウザ内画像処理） | 低 | ○ B の「漫画モード」として内包 |
| D | 同人イベント告知パック（お品書き＋告知スケジュール） | 中（季節性） | Canva（画像のみ） | 高 | 低 | ○ B のモジュール |
| E | 告知×成果の効果測定（なろう API スナップショット） | 中 | 無し | 高 | 低 | ○ B の継続利用・課金理由 |
| F | 漫画のショート動画自動生成 | 高 | YOMcoma β、動画編集アプリ | 中（動画処理は重い） | 低 | △ 後期 |

| H | 作品サイト横断のマルチ投稿（本文を各サイトへ自動投稿） | 高 | 無し | 低 | **高**（なろう規約違反の質問事例あり） | × 採用しない |

**選定：B をコアに、C・D・E をモジュールとして順次追加。** 「小説も漫画も」を掲げるが、最初の実装は「なろう作家 × Bluesky/Misskey/X 併用」という最も条件が揃った層から入る（API が揃っており、移住で多重投稿の痛みが強く、ランキング／コンテストで告知の動機が明確）。

## 3. ツール案：Promotion Assist（仮）

### 3.1 一言で

> **「更新したら、告知は自動で整う」** ── 作品を登録しておくと、更新を検知して SNS ごとに最適化した告知（文・画像・リンク配置・タグ）を用意し、無料 API の SNS には自動投稿、X には安全なワンクリック投稿を提供する、Web 小説・Web 漫画作家専用の告知アシスタント。

### 3.2 対象ユーザー（ペルソナ）

| ペルソナ | 状況 | 主な痛み |
|---|---|---|
| P1 なろう／カクヨム連載作家 | 週 1〜3 回更新。X＋Bluesky を併用。コンテスト応募中 | 更新のたびに 2〜3 か所に貼る。文面が毎回同じ。効果不明 |
| P2 Web 漫画・同人作家 | 月 1〜2 話公開。X/Bluesky/Misskey。年 2〜4 回イベント参加 | 画像整形と多重投稿。イベント前の定型告知 |
| P3 Kindle インディーズ作家 | 巻ごと配信。無料キャンペーンや新刊 | アフィリエイトリンクの管理、告知の継続 |

### 3.3 提供価値（Before / After）

| Before | After |
|---|---|
| 更新 → X で文面を書く → Bluesky 用に短くする → 画像を別ツールで作る → Misskey にも貼る（10〜15 分） | 更新を検知 → 下書きが 3 プラットフォーム分そろう → 確認して「送る」（30 秒） |
| 「宣伝ばかりで申し訳ない」 | 1 日 1 回ガードと言い回しローテーションで、しつこくならない告知に |
| リンクカードが素っ気ない | 冒頭抜粋の縦書きカードや話数バナーを自動生成してリンクカード／添付画像に |
| どの告知が効いたか分からない | なろう API の日次ポイント・ブクマ推移と告知履歴を重ねて表示 |

### 3.4 コア機能（MVP）

1. **作品登録**：なろうは ncode 入力で API から自動入力。カクヨム等は URL 共有（Web Share Target / ブックマークレット）または手入力。
2. **更新検知**：なろうは API ポーリング（差分：話数・最終掲載日時）。他サイトは作者の共有操作をトリガーにする。
3. **告知ジェネレーター**：テンプレート＋変数＋言い回しローテーション。SNS 別に文字数・リンク位置・タグを自動調整。
4. **宣伝画像の自動生成**：縦書き冒頭カード、話数バナー（ブラウザ内レンダリング、フォントは OFL）。
5. **投稿**：Bluesky・Misskey（自動）、Threads（自動、審査後）、X（Web Intent でワンクリック／BYOK で自動）。
6. **ガードレール**：作品×SNS ごとに 1 日 1 回、同一文面の連投禁止、推奨時間帯の提示。

### 3.5 拡張モジュール（v1 以降）

- **漫画モード**：ページ画像を投入すると X 4 枚セット（5p 目以降はツリー）・Bluesky 4 枚・Threads 縦長結合・推奨サイズ再エンコードを生成。1 ページ目に「続きはリプ欄」帯を合成（任意）。
- **イベント告知パック**：イベント情報と頒布物を入れると、お品書き画像＋「1 か月前／1 週間前／前日／当日朝／お礼＋通販」の告知下書きを一括予約。
- **効果測定**：なろう API の日次スナップショット（総合ポイント・ブクマ・週間ポイント・話数）と告知履歴を重ねたグラフ。SNS 側の反応（Bluesky いいね／リポスト、Threads インサイト）を取得。
- **Kindle リンク管理**：アソシエイト ID 付与、無料キャンペーンのカウントダウン告知。
- **AI 文章補助（オプトイン）**：あらすじからのキャッチコピー案、言い回しバリエーション生成。既定オフ。生成物は必ず編集画面を通す。

### 3.6 やらないこと（明示的な非目標）

- 自動フォロー・自動いいね・自動リプライなどのエンゲージメント自動化（スパム扱いになり利用者を危険にさらす）
- 作品サイトへの本文自動投稿・ブラウザ自動操作・スクレイピング
- AI による画像生成（イラスト・表紙）
- X への非公式ルートでの自動投稿

### 3.7 収益モデル（案）

| プラン | 価格 | 内容 |
|---|---|---|
| Free | 0 円 | 作品 1 件、SNS 連携 2 件、手動トリガー、宣伝画像生成、予約 5 件/月 |
| Pro | 月 500 円前後（年 5,000 円） | 作品無制限、更新自動検知、予約無制限、効果測定、漫画モード、イベント告知パック |
| X 自動投稿 | 追加費用なし（BYOK） | 利用者自身の X API クレジットを使用。費用は X に直接支払い |

根拠：作家は価格感度が高く、汎用ツール（月 2,200〜3,000 円台）は「宣伝のためだけ」には払われにくい。月 500 円は「同人誌 1 冊分／コーヒー 1 杯」の心理的ハードル内。Free で価値を体験させ、自動検知と効果測定で Pro 転換を狙う。

### 3.8 成功指標（初期）

| 指標 | 目標 |
|---|---|
| 初回登録から最初の告知投稿までの時間 | 10 分以内 |
| 週間アクティブ作品数（更新検知→投稿が成立した作品） | 登録作品の 40% 以上 |
| 1 作家あたりの週間告知数 | 2 件以上 |
| 3 か月継続率 | 40% 以上 |
| Free→Pro 転換率 | 3〜5% |

### 3.9 検証プラン（開発前 2 週間）

1. Bluesky の創作系フィードと X の #創作クラスタ 周辺で、作家 10 名に 15 分ヒアリング（多重投稿の実態、支払い意思、AI 補助への態度）。
2. ランディングページ＋ウェイトリスト。「更新したら、告知は自動で整う」の 1 行と、縦書きカードのサンプル画像で反応を測る。
3. 手動プロトタイプ：ncode を入れると Bluesky 用の告知文＋縦書きカードが出るだけの 1 画面を作り、実際に投稿してもらう。

## 4. 主要リスクと対策

| リスク | 影響 | 対策 |
|---|---|---|
| なろう API の利用制限が復活 | 更新検知の遅延 | 作品を ncode で最大 500 件まとめて 1 リクエスト、10〜15 分間隔、gzip、キャッシュ。Pro 作品を優先 |
| Threads の App Review に時間がかかる | Threads 自動投稿の提供遅れ | MVP では開発モード（自分のアカウント）で検証し、審査は並行申請 |
| X の規約・料金変更 | X 機能の継続性 | Web Intent を常に用意し、API 依存を最小化 |
| 反 AI 感情による炎上 | 信用失墜 | AI 画像を作らない・AI 文章は既定オフ・使用時は編集必須と明記 |
| カクヨムの規約リスク | 機能縮小 | 作者本人の共有操作のみ。サーバー側からの自動巡回はしない |
| 決済・法務 | 有料化の障壁 | Stripe、特定商取引法表記、プライバシーポリシー、トークンの暗号化保管 |
